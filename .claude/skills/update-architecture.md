# Skill: Update Architecture Docs

## When to Use
After ANY change to system architecture, components, interfaces, or patterns.

## Instructions
1. Read the current `docs/architecture/overview.md`
2. Update it to reflect the current state of the system
3. This is not a changelog — it should always describe what IS, not what changed
4. Update the system diagram if component relationships changed
5. Update the package structure if files were added/moved/removed
6. Update the tech stack table if dependencies changed
7. Update the alignment table if guru-cli correspondence changed
